# Техническое задание: Система утверждения расходов

## 1. Общее описание

Система предназначена для автоматизации процесса подачи и утверждения заявок на расходы. Доступ к системе осуществляется через веб-интерфейс.

## 2. Пользовательские роли

- **Менеджер-финансист (manager):** Сотрудник, создающий заявки на расходы по своему офису.
- **Руководитель (director):** Сотрудник, утверждающий или отклоняющий заявки от всех менеджеров.

## 3. Функциональные требования

### 3.1. Требования для роли "Менеджер-финансист"

- **Просмотр заявок:**
    - Пользователь должен видеть **только свои** заявки в виде списка/таблицы.
    - Таблица должна содержать основные данные: ID, дата, категория, сумма, статус.
    - Должна быть возможность сортировки и простого поиска по своим заявкам.

- **Создание и редактирование заявки:**
    - Пользователь должен иметь возможность создать заявку, заполнив форму со следующими полями:
        - `Категория расхода` (выпадающий список)
        - `Сумма` (числовое поле)
        - `Комментарий` (текстовое поле)
        - `Прикрепление файлов` (возможность загрузить 1 или несколько файлов).
    - Заявка по умолчанию создается в статусе `draft` (Черновик).
    - Пользователь может редактировать или удалить заявку только в статусе `draft`.

- **Жизненный цикл заявки:**
    - Пользователь может отправить заявку в статусе `draft` на утверждение. Статус меняется на `pending` (Ожидает утверждения).
    - После отправки редактирование и удаление заявки блокируется.
    - Пользователь получает уведомление (например, по email) об итоговом решении руководителя (`approved` или `rejected`). В случае отклонения, он должен видеть причину.

- **Копирование заявки:**
    - Должна быть функция "Скопировать" для уже созданной заявки, чтобы быстро создать новую на основе старой.

### 3.2. Требования для роли "Руководитель"

- **Просмотр заявок:**
    - Пользователь должен видеть заявки от **всех** менеджеров-финансистов.
    - Должен быть реализован дашборд с фильтрами по:
        - Периоду дат
        - Статусу (`pending`, `approved` и т.д.)
        - Офису/городу
        - Конкретному менеджеру
        - Категории расхода
    - Список заявок должен поддерживать пагинацию (разбиение на страницы).

- **Утверждение/отклонение заявки:**
    - Для заявок в статусе `pending` руководитель должен видеть всю информацию, включая комментарии и ссылки на скачивание прикрепленных файлов.
    - Должны быть доступны два действия: "Утвердить" и "Отклонить".
    - При выборе "Отклонить" система должна требовать обязательного заполнения текстового поля "Причина отклонения".
    - После принятия решения статус заявки меняется на `approved` или `rejected`.

## 4. Нефункциональные требования

- **Безопасность:** Доступ к системе должен быть защищен аутентификацией (логин/пароль). Пользователи должны иметь доступ только к функциональности, определенной их ролью.
- **Валюты:** Система должна корректно работать с разными валютами, присваивая заявке валюту офиса, в котором она была создана.
